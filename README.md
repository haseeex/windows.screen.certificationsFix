# Windows 屏幕认证修复工具

给 Windows 的「设置 → 系统 → 显示 → HDR 认证」补上正确的认证名称。

---

## 这是什么？

打开 **设置 → 系统 → 显示 → HDR**，你会看到「HDR 认证」这一行：

- 显示 `未找到 HDR 认证的详细信息`
- 或者只显示一个笼统的 `VESA DisplayHDR`，没有具体等级
- 或者明明支持杜比视界，却不显示

**原因**：这一行读的是注册表里的 `DisplayHdrLevel` 值，而这个值**只有显示器厂商的 INF 驱动才会写入**。
很多厂商写得敷衍——只写一条泛称，既不写杜比视界，也不写具体的 DisplayHDR 等级。
用 Windows 自带通用驱动（Generic PnP Monitor）的显示器则完全没有这个值。

**这个工具帮你补上**，让设置页显示完整、准确的认证信息。

> ⚠️ **重要**：这**只改显示的文字标签**，不改变显示器的任何实际能力。
> 你的屏幕能显示什么，改之前和改之后完全一样。

### 操作流程

1. 主菜单用 `↑` `↓` 选中要改的显示器 → `Enter`
2. 认证列表用 `↑` `↓` 移动，`空格` 勾选需要的项 → `Enter`
3. 确认框里确认「修改前 / 修改后」无误 → `Enter` 选「写 入」
4. 看到「写入成功」→ 按任意键返回 → `Q` 退出
5. **重启电脑**（或注销重新登录）

**改完必须重启电脑**才会在设置页生效。

## 这些认证分别代表什么？（作用详解）

先搞清楚每个认证**实际管什么**，再去勾选就不会错。

---

### 一、VESA DisplayHDR —— 画质认证（管「看得爽不爽」）

#### HDR 本身是干什么的

HDR（高动态范围）要解决的是**「亮的更亮、暗的更暗，同时都不丢细节」**。

SDR（传统）画面亮度范围很窄，太阳和阴影只能挤在一个小区间里，结果就是高光一片死白、暗部一片糊黑。
HDR 把范围拉开后：

- 阳光、爆炸、霓虹灯 —— 真正刺眼
- 夜空、隧道、暗室 —— 黑得下去还能看到纹理

**DisplayHDR 就是给「这台屏幕能把 HDR 做多好」打分。**

#### 等级数字 = 峰值亮度（nits / cd/m²）

| 等级 | 峰值亮度 | 实际观感 | 常见机型 |
|---|---|---|---|
| **400** | 400 | 入门级。**HDR 效果很弱**，常被吐槽「假 HDR」 | 千元内办公屏 |
| **500** | 500 | 略有提升，仍属入门 | 中端办公/轻度游戏 |
| **600** | 600 | **开始有 HDR 感觉**，高光能亮起来 | 主流游戏屏 |
| **1000** | 1000 | **真正的 HDR**，高光冲击力明显 | 高端 Mini LED |
| **1400** | 1400 | 很高级别，接近专业监视器 | 旗舰 Mini LED |
| **2000** | 2000 | 目前最高档，机型极少 | 顶级 Mini LED |

> 💡 **为什么 400 被叫「假 HDR」**：
> 400 nits 的峰值和普通 SDR 屏差不多，只是「符合规范」而已。
> 真正能感受到 HDR 差别的门槛大约在 **600 以上**，**1000 才算到位**。

#### 还有哪些隐藏要求

等级不只是亮度，VESA 还同时考核：

| 项目 | 说明 |
|---|---|
| **色域** | 至少 90% DCI-P3（等级越高要求越高） |
| **色深** | 必须支持 10-bit 信号 |
| **黑位** | 局部调光能力（等级越高黑位要求越低） |
| **响应速度** | 从黑到最亮要几帧内完成 |
| **色彩准确度** | ΔITP 误差上限 |

所以「亮度够但色域差」的屏幕拿不到认证。

---

### 二、DisplayHDR True Black —— 画质认证（管「黑得纯不纯」）

**专为 OLED 设立的子系列。**

#### 和标准版的核心差别

| | 标准版 | True Black |
|---|---|---|
| 黑位要求 | 0.02 ~ 0.4 nits | **0.0005 nits**（差 40~800 倍） |
| 适用面板 | LCD / Mini LED | **OLED** |
| 全屏亮度要求 | 较高 | **反而更低** |

#### 为什么全屏亮度反而更低

OLED 每个像素自己发光，全屏高亮会让整块屏发热、加速老化、甚至烧屏。
VESA 承认这个物理限制，把亮度要求下调到合理范围，但把**黑位**提到近乎苛刻的程度。

#### 实际观感差别

- **标准版 1000**：黑场会有轻微「灰雾」（背光漏光），暗部细节可能被光晕糊住
- **True Black 1000**：黑就是纯黑，星空里的星星一颗是一颗

> ⚠️ 两者的设置页**都显示为「DisplayHDR 1000」**，肉眼分辨不出来。
> **LCD / Mini LED 必须用标准版，OLED 才用 True Black** —— 填错就是虚标。

---

### 三、Dolby Vision 杜比视界 —— 画质认证（管「逐帧优化」）

杜比实验室的 HDR 标准，比 HDR10 更高级的地方在于 **动态元数据**。

#### 静态 vs 动态元数据

| | HDR10 | Dolby Vision |
|---|---|---|
| 元数据 | **整部片子一套** | **每一帧一套** |
| 优化方式 | 全片统一色调映射 | 逐帧调整亮度/对比度/色彩 |
| 效果 | 暗场景可能偏亮、亮场景可能偏暗 | 每帧都调到最佳 |

举例：一个从黑暗洞穴走到阳光海滩的长镜头 ——
HDR10 只能用一套参数妥协，杜比视界能在洞穴里压暗、到海滩时拉亮。

#### 局限

- **需要内容、播放器、显示器三方都支持**才有完整效果
- **PC 端支持很有限**（评测原话：「更推荐主机 / 澎湃 OS 端使用」）
- Windows 有 `DolbyVisionHDR` 组件，但实际能用起来的场景不多

> 💡 想真体验杜比视界，用显示器自带的智能系统（如小米澎湃 OS）或接 PS5 / Xbox 更实际。

---

### 四、AMD FreeSync —— 同步认证（管「画面撕不撕裂」）

#### 解决什么问题

显卡渲染速度（帧率）和显示器刷新速度不同步时，画面会出现**撕裂**（上下半屏错位）
或**卡顿**（丢帧抖动）。FreeSync 让显示器刷新率跟着显卡帧率走。

#### 三档区别

| 档位 | 要求 | 效果 |
|---|---|---|
| **FreeSync**（基础） | 支持可变刷新率 | 消除撕裂 |
| **FreeSync Premium** | + LFC（低帧率补偿）+ 1080p 至少 120Hz | 低帧率也不卡顿 |
| **FreeSync Premium Pro** | + **HDR 支持** | 高动态范围下也能同步 |

> 💡 **LFC（低帧率补偿）**：帧率低于显示器最低刷新率时，把同一帧显示两次来「凑数」，
> 避免同步失效。这个功能对低端显卡很重要。

#### Windows 只有两种标签

实测 Windows 11（26100）的资源表，**只认两个 FreeSync 标签**：

| 标签 | 对应档位 |
|---|---|
| `AMD FreeSync with HDR` | Premium Pro（旧名 FreeSync 2 HDR） |
| `AMD FreeSync Premium Pro` | Premium Pro（新名） |

**没有普通 FreeSync，也没有 FreeSync Premium 的标签。**

> 💡 两个是**同一个档位**，2020 年 AMD 把 FreeSync 2 HDR 改名为 Premium Pro，
> Windows 为兼容旧显示器保留了两套 GUID。**只勾一个就行。**

---

### 五、G-SYNC —— 同步认证（NVIDIA 阵营）

#### 三种 G-SYNC 天差地别

| 类型 | 硬件要求 | 额外优势 | 标签可补吗 |
|---|---|---|---|
| **G-SYNC**（硬件） | 显示器内嵌 NVIDIA 专用模块 | 可变过驱、超低延迟、全帧率范围 | 不建议，纯虚标 |
| **G-SYNC ULTIMATE** | 模块 + HDR1000 + 高刷 + 广色域 | 上述全部 + 顶级 HDR | 不建议，型号官网可查 |
| **G-SYNC Compatible**（兼容） | **无**，纯软件 | 基于 Adaptive-Sync，效果接近 | **不用补标签** |

#### 关键：G-SYNC 兼容不需要改注册表

只要显示器支持 Adaptive-Sync / FreeSync / HDMI VRR，就能在
**NVIDIA 控制面板 → 显示 → 设置 G-SYNC** 里勾选「启用 G-SYNC、G-SYNC 兼容」。

**这是驱动级功能，和 `DisplayHdrLevel` 注册表标签完全无关。**

> ⚠️ **为什么不建议补 G-SYNC ULTIMATE**：
> 1. 需要显示器内嵌 NVIDIA 硬件模块，成本极高，现在几乎没厂商做
> 2. G-SYNC ULTIMATE 显示器型号是 NVIDIA 官网**公开可查**的名单，红米/小米不在里面
> 3. 官方参数页自己都说「不支持 G-Sync」

---

### 一句话总结

| 认证 | 管什么 | 你能感受到吗 |
|---|---|---|
| DisplayHDR 400~2000 | HDR 画质强度 | ✅ 高光更亮、暗部更清 |
| DisplayHDR True Black | OLED 的黑位纯度 | ✅ 黑得更彻底 |
| Dolby Vision | 逐帧 HDR 优化 | ⚠️ PC 端受限，主机/智能系统更明显 |
| FreeSync Premium Pro | 防撕裂 + HDR 下同步 | ✅ 游戏画面更顺滑 |
| G-SYNC ULTIMATE | NVIDIA 顶级同步 | ❌ 硬件没有就是没有 |
| G-SYNC Compatible | 软件同步 | ✅ **不用补标签，驱动里直接开** |

## 等级怎么选？（重要，别填错）

先查你显示器的官方参数，看它通过了哪个认证。

### 标准版 vs True Black

| | 适用面板 | 特点 |
|---|---|---|
| **标准版**（400/500/600/1000/1400/2000） | LCD、Mini LED | 常见 |
| **True Black**（400TB/500TB/600TB/1000TB） | **OLED** | 要求黑位 ≤ 0.0005 cd/m²，极严 |

**True Black 的核心要求是「黑得下去」**：黑位必须达到 0.0005 cd/m²，
而标准版最好的 1400 也只要求 0.02 —— 差 40 倍。这不是亮度竞赛，而是黑位竞赛。

反直觉的是，True Black 的**全屏亮度要求反而更低**（因为 OLED 全屏高亮会发热、老化、烧屏）：

| 测试项 | 标准 1000 | True Black 1000 |
|---|---|---|
| 8% 中心白块（峰值） | 1000 | 1000 |
| 全屏长效亮度 | **600** | **500** |

> ⚠️ 注意：`DisplayHDR 1000` 和 `DisplayHDR 1000 True Black` 在设置页**都显示为「DisplayHDR 1000」**，
> 肉眼看不出区别。填错了别人也不知道，但确实是虚标。**LCD / Mini LED 请用标准版，OLED 才用 True Black。**

### 快速判断

- 你的屏幕是 **OLED** → 用 True Black 系列
- 你的屏幕是 **LCD / Mini LED / QD-Mini LED** → 用标准版
- 不确定 → 查官方参数页，或看是否标注了「DisplayHDR xxx True Black」

### 「VESA 通用」那一项是什么（泛称 vs 具体等级）

菜单最上面单独有一组：

```
  VESA 通用（不带等级）
  ▶ [ ] VESA DisplayHDR (泛称)
```

它和下面「标准版」里的具体等级**不是一回事，而是同一信息的粗/细两种粒度**：

| 选项 | GUID | 设置页显示 | 含义 |
|---|---|---|---|
| `VESA DisplayHDR (泛称)` | `E55026B6-…` | **VESA DisplayHDR** | 只说「有 HDR 认证」，**不标等级** |
| `DisplayHDR 1000` | `C624859D-…` | **DisplayHDR 1000** | 精确到具体等级 |

- **泛称**是很多厂商 INF 只写的默认项（小米就是），所以设置页只能看到笼统的「VESA DisplayHDR」
- **具体等级**信息更精确，逻辑上已包含泛称的含义

**建议：两个都勾选。** 泛称是厂商原厂写的，保留它最保险（某些 Windows 版本可能只认泛称）；
具体等级则让设置页显示得更清楚。两者不互斥，可以共存。

> ℹ️ 两者都不勾选也可以 —— 但那样设置页会回到「未找到 HDR 认证的详细信息」。

### 「旧版规范 1.0」那组是什么

VESA 的 DisplayHDR 规范有多个版本迭代：

| 版本 | 发布 | 说明 |
|---|---|---|
| **1.0** | 2017 | 最初版本，测试方法较宽松 |
| **1.1** | 2019 | 收紧了色域、响应时间等要求（**当前主流**） |
| **1.2** | 2024 | 进一步提高色彩准确度、扩大测试范围（最新） |

菜单里的「旧版规范 1.0」那 6 项，就是 1.0 版的 GUID。

**一般不用选它们** —— 现代显示器的厂商 INF 写的都是 1.1 版。
只有在以下情况才考虑：

- 屏幕是很老的产品（2018 年前认证的）
- 厂商 INF 明确写的是 1.0 版 GUID
- 想测试设置页对不同版本标签的显示差异

> ⚠️ **1.0 和 1.1 是互斥的**：勾选 `DisplayHDR 1000 (1.0)` 会自动取消 `DisplayHDR 1000`（即 1.1 版），
> 因为它们属于同一个等级家族。切换版本时不用手动取消。

> ℹ️ **DisplayHDR 1.2 和 NVIDIA HDR 暂不支持**：
> Windows 设置页确实有这两个标签（能从 `SettingsHandlers_PCDisplay.dll` 的资源键里看到
> `DisplayHDR1000_12_Format` 和 `NvidiaHdr_Format`），但它们的 GUID 是微软内部定义的，
> 编译在内核代码里，公开资料和本机文件里都查不到。
> 如果将来找到了，会补进来。

### 「其他」那几项是什么

| 选项 | 含义 | 什么时候选 |
|---|---|---|
| `Dolby Vision 杜比视界` | 杜比实验室的 HDR 标准 | 屏幕支持杜比视界时（查官方参数） |
| `G-SYNC ULTIMATE` | NVIDIA 最高级同步认证 | ⚠️ **几乎不要选**，需要硬件模块，绝大多数显示器没有 |
| `AMD FreeSync with HDR` | AMD 同步 + HDR（旧称 FreeSync 2 HDR） | 屏幕是 FreeSync 2 HDR / Premium Pro 认证时 |
| `AMD FreeSync Premium Pro` | AMD 顶级同步认证（新名称） | 屏幕通过该认证时（查官方参数） |

> 💡 **两个 FreeSync 选项其实是同一个档位。**
> AMD 在 2020 年 CES 把 **FreeSync 2 HDR** 改名为 **FreeSync Premium Pro**，
> Windows 为了兼容旧显示器，保留了新旧两套标签：
>
> | 标签 | GUID | 备注 |
> |---|---|---|
> | `AMD FreeSync with HDR` | `AE040E1F-…` | 旧名（FreeSync 2 HDR 时代） |
> | `AMD FreeSync Premium Pro` | `F9310F0E-…` | 新名（2020 年后） |
>
> **只勾一个就行**，勾两个会在设置页显示两行，看起来重复。
> 选哪个看屏幕厂商 INF 写的哪个（AOC Q27G3Z 写的是旧的 `AE040E1F`）。

> ⚠️ **Windows 只认这两种 FreeSync 标签**（实测 Windows 11 26100）：
> 没有普通版 FreeSync，也没有 FreeSync Premium。
> 这是从 `SettingsHandlers_PCDisplay.dll` 的资源键列表里确认的。

> ⚠️ **G-SYNC 有三种，别搞混：**
>
> | 类型 | 需要什么 | 能否补标签 |
> |---|---|---|
> | G-SYNC（硬件） | 显示器内嵌 NVIDIA 专用模块 | 不建议，纯虚标 |
> | G-SYNC ULTIMATE | 模块 + HDR1000 + 高刷 | 不建议，型号 NVIDIA 官网可查 |
> | **G-SYNC Compatible（兼容）** | **纯软件，基于 Adaptive-Sync** | **不用补标签，NVIDIA 控制面板直接开** |
>
> 只要显示器支持 Adaptive-Sync / FreeSync / HDMI VRR，都能在
> NVIDIA 控制面板 → 显示 → 设置 G-SYNC 里勾选「启用 G-SYNC、G-SYNC 兼容」。
> **这是驱动功能，和注册表标签无关。**

## 命令行用法（进阶）

如果不想用菜单，也可以直接命令行操作：

```powershell
# 1. 以管理员身份打开 PowerShell（Win+X → 终端(管理员)）
cd "本文件夹路径"

# 2. 列出所有显示器（记下你要改的那个「厂商ID」）
.\Set-DisplayCertification.ps1 -List

# 3. 预演（不写入，只显示会改成什么）
.\Set-DisplayCertification.ps1 -VendorId 你的厂商ID -Level 1000 -WhatIf

# 4. 确认无误后真正写入
.\Set-DisplayCertification.ps1 -VendorId 你的厂商ID -Level 1000

# 5. 重启电脑

# 6. 后悔了？还原
.\Set-DisplayCertification.ps1 -Restore
```

### 参数说明

| 参数 | 说明 |
|---|---|
| `-List` | 只列出显示器，不修改 |
| `-VendorId <ID>` | 指定显示器（如 `XMI300A`、`DELA123` 之类，用 `-List` 查自己机器上的值） |
| `-Level <等级>` | `400`/`500`/`600`/`1000`/`1400`/`2000`，或 `400TB`/`500TB`/`600TB`/`1000TB` |
| `-NoDolby` | 不加杜比视界 |
| `-WhatIf` | 预演，不实际写入 |
| `-Restore` | 从备份还原 |
| `-Menu` | 启动交互菜单（等同双击 `运行.bat`） |

不写 `-Level` 时只加杜比视界。

## 安全性

### 自动备份

每次修改前，脚本会自动备份到：

```
C:\ProgramData\DisplayHdrLevel-Backup\HdrLevel-<编号>-<时间戳>.json
```

里面记录了修改前的原值。`-Restore` 或菜单里按 `R` 就能还原。

### 不会写错显示器

脚本不靠猜编号，而是读注册表里的权威映射：

```
Enum\DISPLAY\<厂商ID>\<实例>\Driver = {4d36e96e-...}\<编号>
                                          ↑ 这里才是权威对应关系
```

Windows 给每台显示器分配的 `Class\<编号>` 是**按接入顺序动态变化**的
（同一台显示器在别人电脑上可能是 `0003`、`0005`……），
所以硬编码编号的 `.reg` 文件换台电脑就可能写错到别的显示器上。本脚本没这个问题。

### 影响范围

只改一个注册表值：

```
HKLM\SYSTEM\CurrentControlSet\Control\Class\{4D36E96E-E325-11CE-BFC1-08002BE10318}\<编号>
  └─ DisplayHdrLevel  (REG_MULTI_SZ，多字符串)
```

不动驱动、不动显示设置、不影响实际显示效果。

## 常见问题

### Q：双击 `.bat` 没反应 / 一闪而过？

右键 `运行.bat` → 「以管理员身份运行」。

### Q：双击 `.ps1` 弹出记事本？

Windows 默认用记事本打开 `.ps1`。请用 `运行.bat`，或在 PowerShell 里执行。

### Q：提示「禁止运行脚本」？

`运行.bat` 已带 `-ExecutionPolicy Bypass`，正常不会遇到。
如果手动运行 `.ps1` 遇到，加上：

```powershell
powershell -ExecutionPolicy Bypass -File "完整路径\Set-DisplayCertification.ps1" -Menu
```

### Q：改完重启了，设置页还是没变？

1. 确认写入成功（会弹出「写入成功」提示框）
2. 确认**真的重启了**（注销再登录通常也行，但重启最保险）
3. 确认看的是**正确的显示器**（多屏时设置页可切换）
4. 某些 Windows 版本只认具体等级 GUID，不认泛称——试试换成具体的 400 / 600 / 1000

### Q：界面是乱码 / 边框错位？

1. **乱码**：终端字体不含制表符。Windows Terminal 默认字体就支持，若用的是旧版 cmd 窗口，建议改用 Windows Terminal
2. **边框错位**：终端把某些符号当成了双宽字符。把窗口拉宽一些，或换个等宽字体（如 Cascadia Mono / Consolas）
3. **完全没有边框**：说明当前终端不支持 ANSI。程序会自动退回纯文本菜单，功能不受影响

### Q：能用鼠标点吗？

不能。终端界面只能用键盘。

### Q：会不会影响 HDR 实际效果？

**不会。** 这只是设置页显示的标签。HDR 开关、亮度、色彩都不受影响。

### Q：显示「VESA DisplayHDR」但不显示具体等级？

厂商只写了泛称 GUID（`E55026B6-496B-4ACC-B371-A1211D829ABD`）。
用本工具改成具体等级（如选 `DisplayHDR 1000`）即可。

### 技术实现（供开发者参考）

- **TUI 引擎**：基于 `[Console]::ReadKey($true)` + `[Console]::SetCursorPosition()`，**行级差异重绘**（只重画变化的行），不会闪屏
- **中文宽度**：自己实现了 `Get-DisplayWidth`，按 Unicode East Asian Width 把 CJK 字符算 2 列，并自动跳过 ANSI 转义序列——这是边框能对齐的关键
- **ANSI 颜色**：用 P/Invoke 调 `SetConsoleMode` 开启 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`；失败则自动去色
- **降级机制**：检测到输出重定向（管道 / 日志）时自动退回纯文本菜单，不会崩
- **滚动**：按“渲染行”而非“选项数”滚动，分组标题与空行都算在内
